# 宿主验收执行协议

## 2026-10-31 私人插件版本预检补充

- 开始新的自主宿主轮次之前，先从目标宿主可用的授权接口实际读回原私人插件 ID、版本和当前 release ID。验收方自身通过 Plugin Creator 获取线上 0.2.8 只证明线上状态，不能代替被测新会话确认其实际可见/加载的版本。
- 如目标宿主只有无版本字段的 agency-workflow Skill，且没有可直接读取的插件清单或 Creator 版本元数据，应在提交正式研发试验之前标记环境 BLOCKED；不要通过把版本号写进提示词来伪造版本核验。
- trial-19 曾在无此预检能力时真实提交并被正确阻断，原记录保留；之后任何新轮次须先满足此版本门禁。预检只允许只读查询，不创建试验目录、不发送开发动作、不生成虚假的工具版本证明。
- 最终完整交付还需检查最新 checkpoint revision 与生成任务板一致；只有候选 ready=PASS 不足以证明动态任务板已按最新状态重新生成。出现 stale 报告的轮次必须单独记录 FAIL，不能事后替被测会话回填成 clean PASS。

当前0.2.7使用修订3：新正常轮次13/14/15共用同一目标/授权/清单，第13轮预定后端停点和第二新会话，等价检查见protocol-v3-request-equivalence.json；完整团队A从全新16开始，B/C使用其真实历史。trial-12首次FAIL、未完成的浏览器证据及过期服务不回填成通过。只读采样器声明继续前置，旧修订2作为历史保留。正式执行和首次结果以runs.json为准。

本协议细化已授权四批计划，不替代真实执行。记录保存在build/host-workflow-v2；运行结果由runs.json、独立观察、原始工具返回及项目检查点共同说明。检查点只能证明记录一致性，不能单独证明工具执行。

## 新会话三轮

三个空目录使用同一产品目标、授权和验收清单，仅替换目录编号。顺序执行，避免共享浏览器状态互相覆盖；固定并记录思考强度、插件版本及辅助脚本哈希。不得复制旧实现、注入补救步骤、补造执行时间或改写失败轮次。

至少一轮在开场预定自然结束的阶段停点，再由第二个新会话恢复；这是额外恢复场景，产品目标、授权和最终清单不变。先核对原会话正常结束及文件稳定，随后继续；不把客户端停止按钮当服务端取消凭据。在已核对的现有浏览器窗口中使用独立验收标签，按RuntimeId及已知URL定位，恢复用户原选中标签和最小化状态，不读取或操作其他页面。独立文件观察命令有明确时限和停止标记，仅写验收缓存，不参与宿主执行。

每轮独立保存开始/结束时间、会话URL、可观察调用数、人工纠正和自主返修次数。无法观察调用总数时明确UNKNOWN，不拿事件数代替调用数。源码出现之前以及阶段变更时读回检查点，保存其原始字节、哈希、文件清单和观察时间。正常路径要求：设计交接后按依赖实现、逐任务QA、真实浏览器CRUD/筛选/非法输入、实际停止和同库重启、完整交接与固定候选验证。服务监听127.0.0.1，不安装依赖，不提交Git。

工具超时或页面连接中断单独记录。只读刷新用于恢复显示，不重发开发/发布动作。未知副作用先查实际文件、进程和日志。恢复后仍须完成所有验收，不以局部成功填PASS。人工指出漏测试/漏交接等问题的轮次保留为流程FAIL；环境阻断保留BLOCKED及原因，不充当正常路径通过。

## 综合场景

| 场景 | 执行与证据 | 必须拒绝/保留 |
|---|---|---|
| A 新建交付 | 空目录接入；需求、UX/UI、契约、任务依赖；开发/数据库/测试/审查/安全；固定源码清单与可重复构建包；在本目录隔离测试部署；同一包哈希、实际PID/URL、冒烟、交接 | 缺证据、阻断缺陷、候选变化不重验不能就绪；无用户研究则明确未做访谈 |
| B 已有项目变更 | 使用A的真实项目，先保存稳定包；保留预先存在的用户修改与哈希；执行中提出版本化接口/数据变更；分析受影响任务、失效旧验收、保留未受影响证据；回归及追踪链 | 不覆盖原有修改、不清理历史；植入逻辑/安全缺陷必须先失败并阻断，再修复和保留重跑证据 |
| C 发布事故 | 将已验证包原样部署到隔离目录，核对构建包及解包源码哈希；注入可控服务故障；保留日志和失败探测；诊断后按授权回滚到A的稳定包并核对版本、数据兼容与恢复；复盘进入backlog | 不重建一个不同包冒称同一构建物；不触碰其他服务或生产；PID与目录未核实不得停止进程；未知结果不盲目重复发布 |
| D 中断恢复 | 真实执行中断后保存当时检查点；第二个新会话重核目标与权限，正常继续未完成工作；分别注入外部文件变化、确认丢失的实际局部副作用、缺证据及只读授权，验证正确阻断和调查 | 不倒写任务时间；不靠修改基线绕过外部变化；不把演练注入写成真实生产事故；只读授权不执行发布；未知启动结果先查进程而非重复启动 |

中断、需求变更和故障注入属于预定验收输入，应明确标记演练；它们不是提醒遗漏流程的补救指令。每个负例保存首次结果，恢复或修复不能覆盖它。团队/角色覆盖逐项关联TEAM_FUNCTIONS及ROLE_COVERAGE的场景，只有完整正常/失败行为均有证据才填通过。

## 收尾核对

独立校验全部检查点、候选文件、输出哈希、需求版本、阶段事件顺序、失败重跑和交接。核对SQLite使用同一路径且新旧PID不同；不能把刷新页面当重启。报告注明宿主原始返回、独立复验、模型判断各自来源和没有独立连接器审计的限制。成功率分母不含未确认提交，环境阻断单列；连续三轮仍不支持统计优势结论。更新TASKS/STATUS/ACCEPTANCE_MATRIX并保存无Git快照差异。任何未完成的核心验收保留NOT_RUN/BLOCKED。
