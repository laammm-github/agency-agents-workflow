# 产品需求（PRD）— ChatGPT Workflow Plugin

## 1. 背景
Agency Agents 是以 Markdown 为主体的专业 Agent 角色库和流程说明。希望把其中的指导原则用于 ChatGPT 网页版，以用户现有本地连接器完成真实工作，而不是另起独立 Agent Runtime。

## 2. 用户与首要场景
- 用户：Windows 开发者，已经通过 ChatGPT 使用 OmniTool、浏览器等工具。
- JTBD：描述产品目标或研发任务，ChatGPT 组织完整研发工作：澄清需求、拆解与跟踪任务、设计和实现、测试与修复、审查与验收、按授权发布及运维、保存进度并交接反馈。
- 场景 A（P0）：只读分析指定 Windows 项目，引用具体文件/行并提出建议。
- 场景 B（P0）：修复指定 Bug，保留 diff、测试、只读审查和最终验收。
- 场景 C（P1）：测试指定网页交互，记录真实浏览器观察、失败原因。
- 场景 D（P1）：从 NEXUS Runbook 组建小规模专业团队的顺序工作流。

## 3. 基础能力（中间里程碑，非最终交付）
- FR-01 插件可安装/可发现，在用户任务匹配时触发正确 Skill。
- FR-02 可检索 Agency Agents 原始角色，按需加载定义；严格保持来源引用和版本。
- FR-03 以固定规则完成只读任务路由、工程分析、受控开发与质量门禁。
- FR-04 连接器预检：区分已安装、可调用、允许访问目标电脑与目录四种状态。
- FR-05 所有写操作范围可审计；测试、Diff 和实际工具返回决定完成状态。
- FR-06 任务失败/权限不足/工具断开时停止或上报，不编造输出。
- FR-07 输出结构化报告：目标、角色、操作、证据、状态、遗留风险。
- FR-08 产出符合 portable Agent Plugins 规范的 `plugin.json`、`skills/agency-workflow/SKILL.md` 和可上传 ZIP；按需提供真实注册 App 的绑定版本。
- FR-09 唯一 agency-workflow 只在明确要求 Agency Agents 角色协作或多阶段编排时触发；普通单任务交给现有专用 Skill。外部 Skill 不作为可调用 API 或必需依赖。
- FR-10 开发侧目录与发布侧精选引用闭包分开；发布包离线可读，未包含角色明确提示不可用。

## 4. 非功能要求
- 可维护：上游同步可重复且不覆盖本地定制；每次升级固定上游 commit。
- 安全：最小权限、危险动作确认、不可控/未知状态停止；秘密信息不得落盘。
- 效率：按任务加载最少角色；常规只读研究不启动完整 Dev-QA 循环。
- 透明：必须区分“模型按角色思考”和“运行了独立子 Agent”。
- 可测试：纯数据索引逻辑有单测；工具契约有模拟测试；真实本地验收有可复核记录。

## 5. 明确不做
- 不在 V1 自研文件系统/浏览器/桌面执行器、分布式调度器、心跳与 SQLite 租约。
- 不宣称现成的外部插件自动继承本插件的权限或成为其依赖。
- 不将 `Plugin_...` 实例 ID 当成 MCP App 绑定 ID；任何 `.app.json` 映射需从真实注册 App 获得并验证。
- 不自动执行不可逆操作，不实现远程任意命令代理，不让提示词代替权限策略。
- 不承诺 ChatGPT 普通对话无人值守后台持续工作。
- 不迁移全部 Agent 到上下文；不把 NEXUS 文本直接等同真实运行时。

## 6. 基础里程碑标准（最终交付另须满足第8节）
- 12 个固定场景至少成功 10 个（目标值；须实测）；所有成功陈述都有工具证据。
- 不允许越权写入；失败或连接断开都能正确阻止误报成功。
- 在同类任务上对比无插件基线：记录成功率、工具调用次数、误操作、人工介入和耗时；没有优势则迭代或收缩范围。
- 分级交付：Skills-only 候选包、只读试用、修复能力、浏览器能力分别验收。App 绑定可选，不阻塞 Skills-only。任何对外声明的能力必须通过其全部必需/安全场景；10/12 不能豁免失败处理。
- 首次只读试用：包契约全部通过、新会话实际触发和读取成功、相关缺连接/权限/错误目标/注入场景通过。具体发布门槛见 TEST_PLAN.md。

## 7. 完整研发流程扩展（用户新增范围）
目标从只读分析与前端小修复扩展至通用 Web/服务软件全生命周期；保留分级交付，只读 MVP 只作第一步内部里程碑，不得作为本项目最终交付或替代完整团队功能。18 个角色、职责边界、场景及验收以 [ROLE_COVERAGE.md](ROLE_COVERAGE.md) 为准。
- FR-11 支持需求/计划、UX/UI、架构、前后端/数据、测试/安全/审查、发布/运维及文档反馈阶段的按需组合。
- FR-12 交接保留需求与验收项、产物、证据、风险、跳过理由和下一阶段前置条件；功能修改同步契约/测试/文档。
- FR-13 新增角色逐个具备来源、路由和失败路径验收；全流程声明需 ROLE-01–18 适用项全部通过，不以旧版 10/12 代替。
- 不因角色增加自动获得发布、生产数据迁移、远程扫描、访谈或外发授权。专项技术栈扩展仍需额外场景。

## 8. 完整团队功能：最终必做需求
[TEAM_FUNCTIONS.md](TEAM_FUNCTIONS.md) 的 TEAM-01–14 全部为本轮最终范围，每项需求 ID 与 TEAM 编号一一对应；不是未来待定扩展。包含项目接入、需求和任务管理、研发全流程、缺陷闭环、质量门禁、版本交付、事件反馈、变更决策及跨会话恢复。
最终成功标准：TEAM 功能、ROLE 验收、四条 E2E-TEAM 综合流程和包/安全门槛全部实际验证；旧 10/12 指标只能用于历史基线比较。最终交付涵盖可操作行为与产物，不能仅交付一份团队角色提示词。
